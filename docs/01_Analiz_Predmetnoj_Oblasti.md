# 1 Анализ предметной области и выявление требований на разработку автоматизированной системы поиска вакансий

## 1.1 Исследование предметной области

Перед разработкой автоматизированной системы поиска вакансий необходимо произвести формализацию задач предметной области, а также анализ существующих аналогов, чтобы определить требования к системе.

Процесс трудоустройства в современной цифровой среде включает несколько взаимосвязанных этапов: формирование и публикация резюме, поиск подходящих вакансий на электронных площадках, анализ требований работодателя, подготовка сопроводительного письма, отправка отклика и дальнейшее взаимодействие с рекрутером. Ключевая проблема соискателя заключается не в отсутствии предложений на рынке труда, а в необходимости обрабатывать большой объём разрозненной информации в условиях ограниченного времени.

В рамках предметной области были выделены основные информационные сущности системы: пользователь, учётная запись соискателя, вакансия, отклик, сопроводительное письмо, база данных вакансий, лог операций, фильтр поиска, статистика эффективности. Данные сущности формируют базовый контур системы и отражают фактические действия пользователя: от настройки параметров поиска до анализа результатов отправленных откликов.

Ключевое значение имеют правила взаимодействия с платформой HeadHunter (hh.ru). Так, для отправки отклика необходима авторизованная сессия, корректное резюме, соответствующее вакансии, а для массовой рассылки — учёт ограничений API и антиспам-политики сервиса. Для сопроводительных писем необходимо обеспечить персонализацию под конкретную вакансию, исключив шаблонные сообщения, которые снижают вероятность приглашения на собеседование. Таким образом, система должна обеспечить не только автоматизацию рутинных операций, но и сохранение качества взаимодействия с работодателем.

Для пользователей систем автоматизированного поиска работы являются приоритетными следующие возможности:

– наблюдать полную картину активности по отправленным откликам в текущий момент;

– быстро определять вакансии, наиболее соответствующие профилю соискателя;

– контролировать статус отправленных откликов и полученных предложений;

– отслеживать динамику эффективности поиска (соотношение откликов к приглашениям);

– получать наглядные отчёты и статистику для корректировки стратегии поиска.

Таким образом, при разработке системы важно обеспечить несколько ключевых условий: корректную интеграцию с площадкой hh.ru, удобное управление параметрами поиска и быстрое получение аналитики по эффективности. Именно эти требования определяют архитектурные решения и состав функциональных возможностей системы.

## 1.2 Сравнительный анализ приложений для автоматизированного поиска вакансий

Для выявления сильных и слабых сторон существующих решений были рассмотрены следующие продукты: «Habr Career», «LinkedIn», «SuperJob», «GetMatch» и «Хочу работу в Яндексе». Сравнение проводилось по критериям, которые влияют на практическую применимость системы, а именно: возможность автоматизации отправки откликов, интеграция с конкретными площадками, поддержка персонализации сопроводительных писем, аналитика эффективности, а также удобство использования интерфейса.

Сервис «Habr Career» представляет собой специализированную площадку для поиска вакансий в IT-сфере. Платформа предоставляет API для получения данных о вакансиях, однако не предусматривает инструментов массовой автоматической отправки откликов. Пользователь вынужден вручную просматривать предложения и формировать отклики для каждой позиции отдельно. Преимуществом сервиса является узконаправленная аудитория и качество публикуемых вакансий, недостатком — отсутствие автоматизации рутинных операций и ограниченная аналитика для соискателя.

«LinkedIn» представляет собой глобальную профессиональную сеть с встроенным модулем поиска работы. Платформа поддерживает функцию «Easy Apply», позволяющую отправлять отклики в один клик для вакансий, размещённых непосредственно на платформе. Однако данная функция доступна не для всех вакансий, а персонализация сопроводительных писем остаётся на уровне ручного ввода. Кроме того, российским пользователям доступ к LinkedIn ограничен, что снижает практическую ценность сервиса на локальном рынке труда. Монолитная архитектура платформы не предполагает стороннюю автоматизацию взаимодействия.

«SuperJob» является одним из крупнейших российских сервисов поиска работы, конкурирующих с hh.ru. Платформа предоставляет широкий каталог вакансий и инструменты для публикации резюме, однако инструментов автоматизированной массовой отправки откликов не предусмотрено. Интерфейс сервиса ориентирован на ручной просмотр и отклик. Преимуществом является широкая база вакансий, недостатком — отсутствие средств автоматизации и аналитики для активного соискателя.

«GetMatch» представляет собой сервис автоматического подбора вакансий на основе профиля соискателя. Платформа анализирует резюме и предлагает релевантные позиции, однако процесс отправки откликов остаётся полуавтоматическим: пользователь должен подтверждать каждый отклик вручную. Кроме того, сервис ориентирован преимущественно на соискателей, а не на активное управление множественными откликами. Доступ к полному функционалу частично ограничен платной подпиской.

Телеграм-бот «Хочу работу в Яндексе» и подобные узкоспециализированные боты демонстрируют пример частичной автоматизации: рассылка уведомлений о новых вакансиях, фильтрация по ключевым словам. Однако функционал ограничен уведомлениями, а отправка откликов и формирование сопроводительных писем не предусмотрены. Архитектура таких решений, как правило, закрыта и не позволяет адаптировать под собственные нужды.

Для сравнения и итоговой оценки рассмотренных продуктов была использована следующая шкала критериев с оценкой по баллам:

0 – «критерий практически не реализован»;

1 – «реализован частично»;

2 – «реализован полноценно».

Ни один из рассмотренных продуктов не предоставляет комплексной автоматизации отправки откликов на платформе hh.ru с персонализацией сопроводительных писем и сбором аналитики эффективности. У большинства решений присутствует зависимость от закрытых экосистем и отсутствие возможности адаптации под индивидуальные сценарии соискателя.

На основании сравнения сформирован вывод о целесообразности разработки собственной автоматизированной системы поиска вакансий. Проект будет ориентирован на устранение ограничений, обнаруженных у рассмотренных аналогов: отсутствия автоматизации массовой отправки откликов, невозможности персонализации сопроводительных писем, ограниченной адаптируемости под сценарии соискателя и отсутствия аналитических инструментов для оценки эффективности поиска. В качестве базового подхода выбрана модульная архитектура с веб-интерфейсом управления, позволяющая гибко настраивать параметры поиска, управлять отправкой откликов и анализировать результаты.

Разрабатываемая система будет объединять инструменты автоматизированного поиска вакансий на платформе hh.ru, механизмы формирования и отправки персонализированных сопроводительных писем, базу данных для хранения информации о вакансиях и откликах, а также аналитические отчёты для оценки эффективности поиска. Дополнительно планируется предусмотреть интеграцию с языковыми моделями для генерации качественных сопроводительных писем на основе описания вакансии. Такой подход формирует единый инструмент, который не только сокращает временные затраты соискателя, но и повышает качество взаимодействия с работодателями.

## 1.3 Анализ функциональных требований

На основе анализа предметной области и анализа существующих решений были определены следующие функциональные требования:

– управление учётными записями: добавление, редактирование и удаление аккаунтов соискателей;

– авторизация и поддержка сессий на платформе hh.ru для каждого аккаунта;

– настройка параметров поиска: ключевые слова, регион, уровень зарплаты, опыт работы;

– автоматический сбор вакансий по заданным критериям с платформы hh.ru;

– просмотр, фильтрация и сортировка собранных вакансий в едином интерфейсе;

– формирование и отправка откликов на выбранные вакансии;

– генерация персонализированных сопроводительных писем с использованием шаблонов и языковых моделей;

– управление шаблонами сопроводительных писем: создание, редактирование, привязка к категориям вакансий;

– ведение журнала операций: отправленные отклики, полученные приглашения, отказы;

– контроль статуса отправленных откликов и соответствующих сопроводительных писем;

– формирование аналитических отчётов по эффективности поиска;

– настройка расписания автоматического поиска и отправки откликов;

– управление паузой и возобновлением работы системы;

– экспорт и импорт данных о вакансиях и настройках;

– фильтрация, поиск и постраничный вывод списков данных.

Диаграмма вариантов использования в UML – это графическая модель, которая показывает, какие функции предоставляет система и как пользователь взаимодействует с приложением. На основе выявленных требований можно выделить следующие ключевые варианты использования системы: настройка параметров поиска, запуск автоматического сбора вакансий, просмотр и фильтрация результатов, отправка отклика с сопроводительным письмом, управление шаблонами писем, просмотр статистики эффективности.

Среди основных вариантов использования системы необходимо выделить сценарии настройки поиска, отправки отклика с сопроводительным письмом, анализа эффективности поиска. Сценарий варианта использования «Отправить отклик на вакансию» включает следующие этапы: выбор вакансии из списка, выбор шаблона сопроводительного письма или генерация письма с помощью языковой модели, предпросмотр сформированного отклика, подтверждение и отправка отклика через интеграцию с hh.ru, запись результата в журнал операций.

Сценарий варианта использования «Настроить параметры поиска» включает: выбор учётной записи, указание ключевых слов и категорий, установку фильтров по региону и зарплате, сохранение конфигурации поиска.

Сценарий варианта использования «Проанализировать эффективность поиска» включает: открытие раздела аналитики, просмотр статистики по отправленным откликам, просмотр соотношения откликов к приглашениям, анализ динамики по дням и неделям.

Проведённый анализ функциональных требований позволил определить ключевые варианты использования автоматизированной системы поиска вакансий и формализовать основные пользовательские сценарии взаимодействия с системой. Описанные прецеденты отражают базовые бизнес-процессы приложения и показывают, каким образом пользователь выполняет поиск вакансий, отправку откликов и контроль эффективности. Это подтверждает полноту функционального контура разрабатываемой системы и служит основой для последующего проектирования программных компонентов.

## 1.4 Анализ нефункциональных требований

Нефункциональные требования определяют качество работы системы и условия её практической эксплуатации.

Были сформированы следующие нефункциональные требования:

– безопасность: изоляция данных разных пользователей, безопасное хранение учётных данных для доступа к hh.ru, контроль активных сессий, ограничение частоты запросов к внешним API для предотвращения блокировки;

– производительность: время отклика интерфейса не более 2 секунд, обработка поисковых запросов в фоновом режиме без блокировки UI;

– надёжность: корректная обработка ошибок соединения с внешними сервисами, автоматическое восстановление сессий, сохранение состояния системы при перезапуске;

– масштабируемость: возможность подключения нескольких учётных записей hh.ru, расширение количества одновременных поисковых запросов;

– согласованность данных: соблюдение ограничений на уровне базы данных, корректная синхронизация статусов откликов с данными hh.ru;

– сопровождаемость: модульная структура кода, разделение компонентов сбора данных, обработки и интерфейса;

– развёртываемость: контейнеризация и запуск через Docker, минимизация зависимостей от внешней инфраструктуры;

– удобство использования: минимизация числа шагов для запуска поиска и отправки откликов, наглядное отображение статусов операций, интуитивно понятный веб-интерфейс;

– тестируемость и контролируемость качества: поддержка модульных и интеграционных тестов, логирование ключевых операций для диагностики.

Разработка автоматизированной системы поиска вакансий должна быть реализована с применением веб-технологий. Серверная часть должна быть реализована на языке Python с использованием фреймворка FastAPI. Пользовательская часть должна реализовываться как веб-приложение с использованием HTML, CSS и JavaScript. Для хранения данных должна использоваться встраиваемая база данных SQLite. Интеграция с платформой hh.ru должна осуществляться через API и механизмы веб-скрапинга с соблюдением ограничений на частоту запросов. Взаимодействие с языковыми моделями должно быть реализовано через API внешних провайдеров с возможностью настройки параметров подключения.

Система должна разворачиваться в контейнерной среде Docker и корректно исполняться на ОС семейства Windows (10 и выше) и Linux. Клиентская часть должна быть оптимизирована для современных браузеров: Google Chrome, Mozilla Firefox, Microsoft Edge, Apple Safari. Дополнительно предусматривается адаптивный дизайн веб-интерфейса для удобной работы на устройствах с различным разрешением экрана.
